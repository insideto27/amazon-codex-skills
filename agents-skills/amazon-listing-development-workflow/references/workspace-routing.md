# Workspace Routing

Use the product's current Feishu directory as the authority. Read the workspace governance manual and asset index, then list the relevant product folder immediately before writing. The index is a snapshot; current directory contents take precedence. Never restore a deleted directory from an old template or prior conversation.

Where a product already has the following folders under `03_Listing与链接`, respect their status meanings:

| Folder | Purpose |
|---|---|
| `01_当前发布版` | The version actually published in Seller Central |
| `02_图片与A+` | Images and A+ assets; never store text iterations here |
| `03_变体关系及评论` | Variation and review assets; never store text iterations here |
| `04_Listing迭代版本` | All newly developed, candidate, testing, and pending-publish listing versions |
| `99_历史版本` | Replaced live versions and explicitly retired tests |

If an existing `04_Listing迭代版本` is available, use it for new candidate versions. If it is absent, use an existing product-specific Listing destination only when its current contents and governance purpose make candidate storage clear (for example an established `03_Listing研发/listing` folder). A compliance-only `HOLD` or `BLOCK` record belongs in an existing product compliance module when that is the suitable current location. A missing module or ambiguous destination is not permission to create one. Present the result in chat or another authorized location and report the gap; wait for the user's explicit directory instruction before creating any folder.

Do not create year or variant subfolders, move a candidate to `01_当前发布版`, move a live version to history, rename or delete a version, or alter permissions without an explicit request. Existing drafts in a Listing root do not authorize moving them.

Before writing, inspect the suitable existing destination and relevant prior-version locations to avoid duplicate names and determine the next version number. After writing, report the normalized title, actual full folder path, and URL.
